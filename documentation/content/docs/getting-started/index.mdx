Install the workflow package:

```bash
bun add @promin/workflow @spilne/perfect-core   # Durable workflows
```

Optional packages for specific use cases:

```bash
bun add @promin/data         # DataFrame, profiling, diff, quality checks
bun add @promin/postgres     # Postgres workflow storage, step queue, scheduler
bun add @promin/redis        # Redis workflow storage, step queue, scheduler
bun add @promin/sqlite       # SQLite workflow storage, step queue, scheduler
bun add @promin/workflow-remote  # workflow storage and workers over HTTP
bun add @promin/duckdb       # DuckDB executor for analytical queries
```

## Package overview

Promin is built on [perfect](https://github.com/spilne/perfect). For resilient async actions, streams with backpressure, and concurrency primitives, use `@spilne/perfect-core` directly.

| Package | What it provides |
|---------|-----------------|
| `@promin/workflow` | Durable workflows, DAG steps, compensation, distributed workers, schedulers, SQL models |
| `@promin/data` | DataFrame, data profiler, diff, quality, contracts |
| `@promin/postgres` | Postgres workflow storage, step queue, scheduler, leases, registries |
| `@promin/redis` | Redis workflow storage, step queue, scheduler, state machine storage |
| `@promin/sqlite` | SQLite workflow storage, step queue, scheduler |
| `@promin/workflow-remote` | Workflow storage and worker RPC over HTTP |
| `@promin/duckdb` | DuckDB executor for analytical queries |

## Your first Workflow

Durable workflows survive crashes. Each step is persisted — on restart, completed steps are skipped automatically.

```typescript
import { createWorkflowRunner, InMemoryWorkflowStorage, workflow } from "@promin/workflow";

declare function validate(order: { id: string }): Promise<{ id: string; total: number }>;
declare function charge(order: { id: string; total: number }): Promise<{ chargeId: string }>;
declare function refund(chargeId: string): Promise<void>;
declare function ship(chargeId: string): Promise<{ trackingId: string }>;

const orderFlow = workflow<{ id: string }>({ name: "process-order" })
  .stepAsync("validate", ({ input }) => validate(input))
  .stepAsync("charge", ({ prev }) => charge(prev), {
    compensate: ({ result }) => refund(result.chargeId),
  })
  .stepAsync("ship", ({ prev }) => ship(prev.chargeId))
  .build();

// A Workflow is plain data; a runner executes it against a storage.
const runner = createWorkflowRunner({ storage: new InMemoryWorkflowStorage() });
const result = await runner.run({ workflow: orderFlow, workflowId: "order-1", input: { id: "1" } });
```

If "ship" fails for good, the run compensates the completed "charge" step (refund) and then fails — a saga with no extra code. Running the same `workflowId` again after a crash resumes from the last checkpointed step; running a completed one returns its stored result. Swap `InMemoryWorkflowStorage` for Postgres, Redis or SQLite storage to survive restarts.
